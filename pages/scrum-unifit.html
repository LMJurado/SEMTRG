Metodología Scrum aplicada al proyecto UniFit

1. Identificación y análisis de necesidades

Se inicia identificando las necesidades del Gimnasio Universitario de la Universidad de Nariño mediante observaciones, revisión de registros y entrevistas a usuarios, monitores y administradores. Con esta información se determinan los problemas relacionados con la gestión de rutinas, alimentación, seguimiento de entrenamientos y disponibilidad de información.

Posteriormente, se establecen los requisitos funcionales y no funcionales de UniFit, definiendo las características que debe cumplir la aplicación. Todos estos requisitos se organizan en el Product Backlog, una lista priorizada que permite identificar las funcionalidades más importantes y orientar el desarrollo del proyecto.

2. Planificación de los Sprints

Una vez definidos los requisitos, se organiza el trabajo en ciclos de desarrollo denominados Sprints. Para UniFit se establecen cinco Sprints, cada uno con una duración aproximada de cinco semanas y un objetivo específico. Durante esta etapa se seleccionan las funcionalidades que se desarrollarán, se determinan las actividades necesarias y se establecen los resultados esperados.

La planificación contempla los fundamentos de la aplicación, el módulo de rutinas, nutrición, inteligencia artificial y estadísticas. Esta organización permite distribuir el trabajo progresivamente, controlar los avances y realizar ajustes cuando las necesidades del proyecto lo requieran.

3. Diseño y desarrollo incremental

En esta etapa se construye progresivamente UniFit a partir de los requisitos priorizados. Se define la arquitectura tecnológica utilizando Flutter, Firebase y TensorFlow Lite, se diseña el modelo de datos y se elaboran las interfaces de usuario. Posteriormente, se desarrollan los módulos de autenticación, rutinas, nutrición, estadísticas y administración.

También se integran las funcionalidades de inteligencia artificial para el reconocimiento de alimentos, estimación de postura y asistencia mediante IA Coach. Cada funcionalidad se implementa de manera incremental, realizando pruebas de funcionamiento e integración para comprobar que los componentes respondan correctamente.

4. Revisión y validación de incrementos

Al finalizar cada Sprint se revisan las funcionalidades desarrolladas para verificar que cumplan los requisitos y criterios de aceptación establecidos. En el caso de UniFit, esta revisión contempla comprobar el registro de entrenamientos, la consulta de rutinas, el funcionamiento de los registros alimentarios, las estadísticas y las herramientas de inteligencia artificial.

También se recopilan observaciones de usuarios y monitores para identificar errores, dificultades de navegación o funcionalidades que necesitan ajustes. Los resultados permiten determinar si el incremento desarrollado está listo para integrarse con los demás componentes y establecer nuevas prioridades para los siguientes ciclos de trabajo.

5. Retroalimentación y mejora continua

Después de cada revisión se realiza una reflexión sobre el proceso de desarrollo, identificando los aspectos que funcionaron correctamente y aquellos que necesitan mejorarse. En UniFit, esta actividad permite analizar las dificultades técnicas, los errores encontrados, el cumplimiento de las actividades y las observaciones recibidas durante las pruebas.

A partir de estos resultados se establecen acciones correctivas para los siguientes Sprints, como mejorar las interfaces, optimizar el rendimiento, corregir funcionalidades o ajustar los componentes de inteligencia artificial. Esta retroalimentación permite adaptar continuamente el desarrollo y mantener una evolución progresiva de la aplicación.

6. Implementación y prueba piloto

Una vez alcanzada una versión funcional de UniFit, se prepara su implementación controlada en el Gimnasio Universitario. Se selecciona una muestra intencional de entre 10 y 20 usuarios, además de los monitores y personal administrativo participantes. Se coordinan los permisos institucionales, se crean las cuentas, se cargan los catálogos y se realiza una capacitación sobre el funcionamiento de la aplicación.

Posteriormente, los participantes utilizan UniFit en condiciones reales durante el periodo establecido. Se recopilan registros de uso, observaciones e incidentes, manteniendo el registro manual del gimnasio como respaldo durante la prueba piloto.

7. Evaluación de resultados y cierre

Finalmente, se analizan los resultados obtenidos durante la prueba piloto para determinar la usabilidad, el funcionamiento técnico y la utilidad percibida de UniFit. Se utilizan instrumentos como la escala SUS, cuestionarios, entrevistas, observación de tareas y registros del sistema.

También se revisa el desempeño de los componentes de inteligencia artificial y los patrones de utilización de la aplicación. Los resultados cuantitativos y cualitativos se integran para identificar fortalezas, dificultades y oportunidades de mejora. Como producto final se elabora un informe con los hallazgos, las limitaciones del proyecto y las recomendaciones para futuras versiones.
