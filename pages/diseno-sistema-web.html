Metodología IWEB

Historia

En 1998, Roger Pressman moderó una mesa redonda virtual con representantes de la ingeniería de software tradicional y del desarrollo de software basado exclusivamente en Internet. El debate se centró en determinar si era conveniente aplicar un proceso de ingeniería a las aplicaciones basadas en Internet o qué características de estas justificaban un enfoque diferente.

La conclusión general fue que aplicar un proceso de ingeniería no es una mala idea; sin embargo, este debe adaptarse a los requerimientos de cambio continuo y rapidez propios del desarrollo web. De iniciativas como esta, junto con la organización de congresos y talleres especializados, surgió una disciplina denominada Ingeniería Web (IWeb).

¿Qué es la metodología IWEB?

La Ingeniería Web es una disciplina enfocada en la creación, implementación y mantenimiento de aplicaciones y sistemas web. Se relaciona con el establecimiento y la utilización de principios científicos, de ingeniería y de gestión, así como con enfoques sistemáticos y disciplinados para favorecer el desarrollo exitoso, la gestión y el mantenimiento de aplicaciones web de alta calidad.

Modelo IWEB

El modelo organiza el desarrollo de una aplicación web en fases que permiten definir las necesidades, planificar el trabajo, analizar los requisitos, diseñar la solución, construirla y evaluar su calidad.

Fase 1. Formulación

Consiste en identificar los requerimientos y las metas de la organización para construir la aplicación web. Para recopilar información se pueden utilizar técnicas como entrevistas, cuestionarios y muestreo.

Fase 2. Planificación

Su objetivo es estimar el costo global del proyecto y evaluar los riesgos asociados al desarrollo de la aplicación web.

Las actividades principales son:

  1. Definir el alcance y los recursos necesarios, incluidos los gestores del proyecto IWeb, el personal técnico y el cliente.
  2. Establecer los costos, la planificación temporal y los mecanismos de seguimiento y revisión de la gestión.
  3. Proporcionar un enfoque general del desarrollo de la aplicación web a todas las personas relacionadas con el proyecto.
  4. Describir cómo se garantizará la seguridad de la aplicación.

Fase 3. Análisis

Consiste en establecer los requisitos técnicos de la aplicación web e identificar los elementos de contenido y los requisitos de diseño gráfico que se incorporarán. Comprende cuatro tipos de análisis:

  1. Análisis del contenido. Examina los contenidos que se ofrecerán en la aplicación, como textos, gráficos, imágenes, videos y sonidos.
  2. Análisis de interacción. Describe la interacción entre el usuario y la aplicación web, incluidas las acciones que puede realizar y las respuestas del sistema.
  3. Análisis funcional. Detalla las funciones, operaciones y servicios que deberá ofrecer la aplicación web.
  4. Análisis de configuración. Describe el entorno tecnológico y la infraestructura en los que funcionará la aplicación.

Fase 4. Ingeniería

Comprende el diseño de los componentes principales de la aplicación web para establecer su estructura, organización, navegación y presentación.

  1. Diseño arquitectónico. Define la estructura global de la aplicación y la organización de sus componentes. También contempla patrones y plantillas que facilitan la reutilización y construcción del sistema.
  2. Diseño del contenido. Establece la estructura y el formato de la información. Las estructuras pueden ser lineales, reticulares, jerárquicas o de red, también llamadas estructuras de web pura.
  3. Diseño de navegación. Define las rutas para acceder al contenido y a los servicios. Incluye identificar las necesidades de navegación de los distintos tipos de usuarios y establecer mecanismos y estructuras para acceder a las secciones y funcionalidades.
  4. Diseño de la interfaz de usuario. Identifica los elementos y acciones de la interfaz y define la distribución visual de las pantallas que servirán como base para el prototipo. Considera las necesidades del usuario, las tareas que realizará y el entorno de uso.

Fase 5. Diseño de las estructuras de datos

Transforma el modelo del dominio de información elaborado durante el análisis en las estructuras de datos necesarias para implementar el software. Define la organización, las relaciones y la forma de almacenar y gestionar la información que requiere la aplicación web.

Fase 6. Generación de páginas

Es una actividad de construcción que utiliza herramientas automatizadas para crear páginas web. Su propósito es convertir los diseños y las especificaciones de las fases anteriores en páginas funcionales, integrando contenidos, navegación y componentes de la aplicación.

Fase 7. Puesta a prueba y evaluación del cliente

El software se somete a pruebas para identificar errores antes de su entrega. El objetivo es comprobar que la aplicación cumple los requisitos establecidos y funciona correctamente.

Las principales actividades son:

  1. Comprobar la lógica interna de los componentes web y verificar que funcionen según las especificaciones.
  2. Verificar los dominios de entrada y salida del programa para identificar errores de funcionalidad, comportamiento y rendimiento.
  3. Evaluar la aplicación con el cliente para confirmar que las funcionalidades satisfagan sus necesidades y requerimientos.
  4. Realizar los ajustes necesarios, corregir los errores detectados y mejorar los aspectos que no cumplan las expectativas del cliente.

La evaluación final permite determinar si la aplicación web está preparada para su entrega y puesta en funcionamiento.
